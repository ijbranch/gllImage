## [In-Service]

### Added
- (2026-10-21) `RenderMode` ( `rmNormal`, the default, or `rmSkia` ) on `TgllImageView` and `TgllDBImage`, and the optional Skia renderer that serves it — `gllImage.View.pas`, `gllImage.DB.pas`, `gllImage.Skia.pas` (new), `gllImageSkiaR.dpk` / `.dproj` (new), `gllImage.groupproj`, `TestGllImageSkia.pas` (new), `gllImageTests.dpr`, `gllImageTests.dproj`, `README.md`, `Users Guide.md`, `Help.md`.  **Problem:** on a 32-bit display the VCL's `StretchDraw` shrinks by dropping whole rows and columns ( `STRETCH_DELETESCANS`, `Vcl.Graphics.pas` 8452: `HALFTONE` only on displays of 8 bits or fewer ), so a 12 MP photo fitted to a viewer showed moire and broken small text.  **Fix:** both scaled draws in `Paint` now go through `DrawScaled`; with `rmSkia` and a renderer registered, `TgllSkiaImageRenderer` draws the picture with trilinear filtering and mipmaps when shrinking and cubic when enlarging, from a Skia image decoded once ( from the VCL's own decode, so formats, EXIF and colours are unchanged ), rendering only the visible part and caching it.  A generation counter bumped whenever the drawn picture changes keys the cache.  It declines metafiles, icons, animated GIFs, colour-keyed transparency and 1:1 draws, which stay on `StretchDraw`; without `gllImage.Skia` linked, `rmSkia` draws as `rmNormal` and says so once through `OutputDebugString`.  **Why a plug-in:** `gllImageR` keeps its only dependency LibJxl; `gllImageSkiaR` ( requires `gllImageR`, `Skia.Package.RTL`, `Skia.Package.VCL` ) is linked only by applications that opt in.  Raster rendering only, safe under VirtualUI.  8 tests ( 50 in the suite ): 1-px stripes shrunk 4:1 and 13:1 come out mid-grey with Skia ( StretchDraw keeps whole columns, and the 13:1 case shows cubic without mipmaps aliasing to 28..227 ).  Mutation-checked: disabling the Skia path, nearest sampling, cubic for shrinking, a cache that ignores the generation, and dropping the 1:1 decline are each KILLED.
- (2026-10-19) OLE drag and drop (`EnableDragDrop`): virtual files can be dropped as well as files from Explorer (an Outlook attachment, an image from a web browser or a zip folder), written to a temporary folder for the length of the drop; the shell's drag image shows over the control; a read-only or disabled control shows the no-drop cursor.  `WM_DROPFILES` remains the fallback when OLE cannot be initialised.  **Why:** the suite's picture forms needed gllDragAndDrop for attachments; the control now does it with nothing beyond the RTL and VCL — `gllImage.DragDrop.pas`, `gllImage.View.pas`, `gllImageR.dpk`, `gllImageR.dproj`
- (2026-10-19) Drag-out (`EnableDragOut`, `DragOutFileName`): the picture is dragged to Explorer or another program as a file in its own format; `TgllDBImage` writes the field's bytes as stored, an unposted rotation or flip included.  `GraphicClassExtension` / `GraphicFileExtension` name a format's file.  The demo turns it on in both controls — `gllImage.View.pas`, `gllImage.DB.pas`, `gllImage.Utils.pas`, `gllImage.Consts.pas`, `Demo.Main.pas`
- (2026-10-19) Tests of the drop target, virtual files, safe file names and drag-out (42 tests) — `TestGllImage.pas`, `gllImageTests.dpr`, `gllImageTests.dproj`, `gllImageDemo.dpr`, `gllImageDemo.dproj`
- (2026-10-19) `TgllImageView`, the stand-alone viewer (the `TImage` counterpart), and `TgllCustomImageView`, the base both controls share, so the viewer and the data-aware control never drift apart — `gllImage.View.pas`
- (2026-10-19) JPEG XL: detected by signature and decoded by LibJxl's `TJxlImage`; `SaveToFile` writes `.jxl`; LibJxl is the one dependency beyond the RTL and VCL.  Formats registered with `TPicture` are tried when no signature matches — `gllImage.Utils.pas`, `gllImage.View.pas`
- (2026-10-19) Scroll bars (`ScrollBars`): shown while the zoomed picture overhangs the control; the wheel scrolls with them (Shift+wheel horizontally) and Ctrl+wheel zooms — `gllImage.View.pas`
- (2026-10-19) `RotatePicture`: turns the pixels as seen (display rotation included) and keeps the format; `ZoomBy`; `PanBy`; `ScrollPosition`; `ShowContextMenu`; `OnFilesDropped` (every dropped file, `Handled` to take the drop over) — `gllImage.View.pas`
- (2026-10-19) `Stretch` / `Proportional` (not stored), so a VCL `TDBImage` form converts by its class name; `RegisterClassAlias( TgllDBImage, 'TGDBImage' )` for forms that still name the GITLAKDB class — `gllImage.View.pas`, `gllImage.DB.pas`
- (2026-10-19) Packages `gllImageR` / `gllImageD` (Win32 + Win64), the group project, the DUnitX suite, the demo with two JPEG XL samples, and the documents — `gllImageR.dpk`, `gllImageD.dpk`, `gllImage.groupproj`, `gllImage.Consts.pas`, `gllImage.Register.pas`, `gllImageTests.dpr`, `TestGllImage.pas`, `gllImageDemo.dpr`, `Demo.Main.pas`, `Demo.Main.dfm`, `Sample-Landscape.jxl`, `Sample-Portrait.jxl`, `README.md`, `Help.md`, `Users Guide.md`, `.gitignore`

- (2026-10-19) `ZoomIn`, `ZoomOut` and `ZoomBy` on a fitted picture continue from the scale shown; they used to change nothing visible — `gllImage.View.pas`

### Removed
- (2026-10-19) The optional GraphicEx support: TIFF decodes through the VCL's `TWICImage` — `gllImage.Utils.pas`

### Fixed
- (2026-10-19) `TgllDBImage.LoadFromFile` re-encoded the file on Post: it marked the record modified after writing the file's bytes, so `UpdateData` replaced them with the picture re-encoded (a lossy second generation for JPEG XL, a re-compressed PNG).  The bytes are now stored as they are — `gllImage.DB.pas`
- (2026-10-19) Pan limits ignored the display rotation (a picture turned 90 degrees could not be panned along its long side), allowed a symmetrical range for an uncentred picture (half of it unreachable, an empty band draggable into view), and kept a stale offset when the picture went — `gllImage.View.pas` (`ClampPanOffset`)
- (2026-10-19) With `MaintainAspectRatio` off a fitted picture was drawn at 1:1 instead of stretched to the control — `gllImage.View.pas` (`Paint`)
- (2026-10-19) A BLOB written by the VCL's `TDBImage` (an 8-byte header before the bitmap) was reported as an unknown format — `gllImage.Utils.pas` (`StripLegacyGraphicHeader`)
- (2026-10-19) `SaveToFile` with a `.jxl` name wrote the graphic's own format under that name — `gllImage.View.pas`
- (2026-10-19) `ImageFormat` called a JPEG XL "Bitmap" (`TJxlImage` descends from `TBitmap`) — `gllImage.View.pas`
- (2026-10-19) The palette icon was named `TEDBIMAGE` (the ElevateDB-era class), so `TGDBImage` never had one; both controls now do — `gllImage.Register.dcr`
- (2026-10-19) Assigning a picture before the control had a parent raised "has no parent window" (the layout read `ClientWidth`) — `gllImage.View.pas` (`GetViewClientSize`)
